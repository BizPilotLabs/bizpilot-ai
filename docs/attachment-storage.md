# Attachment Storage

## Architecture

Attachments are stored in private Cloudflare R2 using its S3-compatible API. The backend owns authorization, object-key generation, presigned URL creation, finalization, metadata persistence, deletion, RBAC, audit logging, and tenant isolation.

Only task attachments are currently supported because the Prisma `Attachment` model relates to `Task`.

## Upload sequence

1. The frontend calls `POST /tasks/:taskId/attachments` with original filename, MIME type, and file size.
2. The API authenticates, checks `attachments.create`, validates the task belongs to the authenticated organization, validates file metadata, creates a pending attachment row, generates a tenant-scoped object key, and returns a short-lived presigned PUT URL.
3. The frontend uploads directly to R2 using the returned URL and headers.
4. The frontend calls `POST /attachments/:id/complete`.
5. The API verifies the pending attachment belongs to the authenticated organization, verifies the R2 object exists, checks content length and content type when available, marks the attachment `READY`, and records `attachment.upload`.

## Download sequence

The frontend calls `GET /attachments/:id/download`. The API checks `attachments.read`, validates tenant ownership, and returns a short-lived presigned GET URL. The bucket remains private.

## Delete behavior

The API checks `attachments.delete`, validates tenant ownership, attempts R2 object deletion, then soft-deletes metadata and records `attachment.delete`. R2 delete is idempotent for missing objects.

## Environment variables

Use `STORAGE_PROVIDER=disabled` for local development without uploads. Use `STORAGE_PROVIDER=r2` with:

- `R2_ACCOUNT_ID`
- `R2_ACCESS_KEY_ID`
- `R2_SECRET_ACCESS_KEY`
- `R2_BUCKET_NAME`
- `R2_ENDPOINT` optional
- `R2_PRESIGNED_UPLOAD_EXPIRES_SECONDS`
- `R2_PRESIGNED_DOWNLOAD_EXPIRES_SECONDS`

Secrets belong only in the API environment. They must never be exposed through Vite variables.

## Object keys

Keys are generated by the backend:

`organizations/{organizationId}/tasks/{taskId}/attachments/{attachmentId}/{sanitizedFilename}`

The frontend never supplies storage keys.

## Allowed files

Maximum size: 25 MB.

Allowed MIME types: PDF, DOCX, XLSX, PPTX, TXT, PNG, JPG, JPEG. Filename extension must match the declared MIME type.

## CORS

R2 bucket CORS must allow the deployed frontend origin, `PUT` and `GET`, and the `content-type` header. Do not use wildcard origins in production.

## Orphan cleanup

Pending uploads expire. `AttachmentService.cleanupExpiredPendingUploads()` soft-deletes expired pending rows and best-effort deletes their objects. A scheduled command can call this method in a future operations milestone.

## Security limitations

This milestone does not include malware scanning, OCR, AI processing, media transformation, or asynchronous quarantine workflow. Antivirus scanning remains a future production-hardening requirement.
